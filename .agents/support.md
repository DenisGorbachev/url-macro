# Project support

- Shell scripts must support GNU/Linux and Bash and BSD command-line tools bundled with macOS 15.

## Cargo.toml

- Must contain:
  - `workspace`:
    - `package`.
    - `metadata`:
      - `details`:
        - `name`.
        - `title`.
    - `lints`.
  - If `package` exists:
    - Then: `package`:
      - `metadata`:
        - `details`.
- Every workspace package manifest must contain `lints.workspace = true`.
- Must not contain:
  - `workspace`:
    - `package`:
      - `description`.
      - `readme`.
  - `package`:
    - `readme`.

## README.ts

- Must support regular package, root package with workspace members, virtual workspace.
- Must use `cargo metadata` to discover workspace packages, manifests, targets, resolved properties.
- Must normalize GitHub origin URLs and validate every non-empty package repository against origin.
- For root repository check, must prefer `workspace.package.repository` and fall back to resolved root `package.repository`.
- If `package.metadata.details.readme.generate ?? workspace.metadata.details.readme.generate ?? true` is `true` for README:
  - Then: must enable it.
- If README is enabled:
  - Then:
    - Must generate one README beside every workspace package manifest.
    - Must generate `Other packages` section in root package README.
    - Must generate heading and package README links at repository root for virtual workspace.
- Must choose titles in this order:
  - Package README: non-empty `package.metadata.details.title`, then `package.name`.
  - Virtual workspace: non-empty `workspace.metadata.details.title`, `package.metadata.details.title`, `workspace.metadata.details.name`, then `package.name`.
- Package READMEs must derive installation, usage, binaries, crate docs, badges, license links from package metadata and targets.
- GitHub-specific content must be limited to public GitHub repositories; non-GitHub repositories must not require GitHub metadata.
- Must render all targets to temporary files before replacing any destination, then remove remaining temporary files.
- Partial destination replacement failure is acceptable because committed READMEs will be regenerated by next successful `fix:readme`.
- Must write README files directly, without output arguments or generated content on standard output.

## AGENTS.ts

- Must preserve `renderXmlFile`, `runAgentDocsList`, `includeAgentDocs`, `includeAllFiles`.
- If `.agents/project.md` is present:
  - Then: must include it.
- Must use `cargo metadata` to:
  - Include requested files only from workspace members, plus root `Cargo.toml`.
  - Include repository docs for dependencies used directly by workspace member.
  - Include requested dependency-owned docs from any matching metadata package, selecting highest version, then manifest path, before checking whether file exists.
- Included paths must be repository-relative and sorted.
- If requested path is absent:
  - Then: must skip it.
- Must preserve Markdown heading shifts and collision-safe language-tagged code fences.
- Must render to temporary file beside `AGENTS.md`, replace it only after success, clean up temporary file.

## .mise/tasks/fix/name.sh

- Must accept optional target name, defaulting to `git:repo-name`.
- Must read current name from `workspace.metadata.details.name`, falling back to `package.name`; missing or empty names must fail.
- Must normalize periods before deriving kebab- and snake-case names; `package.name` fallback target must be kebab-case.
- Must rename matching names in:
  - Root and member manifests, including package names, members, default members, dependencies, local paths.
  - Rust crate references outside `specs` and `.agents`.
  - Package directories derived from member manifest paths.
- Must not assume package directory layout or rename workspace root.
- Must rename nested directories before parents and fail on existing destinations.
- Must refresh existing `Cargo.lock` with `cargo metadata`, then validate full graph with `--locked`; validation without lockfile must not create one.
- Must update original name source: raw workspace metadata or kebab-case root package name.
- Must roll back every file edit and directory move on failure, then remove transaction data.

## fnox.toml

- Must contain `env = "exec"`.
- Must contain `providers.age`.
  - Must have `type = "age"`.
  - Must contain `recipients` array with at least two unique native age recipients.
  - Template baseline recipients must be host LAK and sandbox LAK.
  - GitHub repository with test secrets must additionally contain its repository-specific CAK recipient.
- Every key under `profiles.test.secrets` must have `provider = "age"`.

## .mise/tasks/fix/fnox.sh

- Must declare `wait_for=["fix:name"]`.
- Must validate that `providers.keychain.service` equals `git:repo-name`.
- Must not migrate secrets between old and new identifiers.

## .mise/tasks/fnox/github/init-age-key.sh

- May clear clipboard without preserving contents that predate task.
- May treat write races as acceptable because script is run by single user who guarantees that other scripts do not run concurrently.

## .mise/tasks/fix/cargo.sh

- Must declare `wait_for=["fix:name"]`.
- Must discover workspace package manifests with `cargo metadata`.
- If manifest has no `lints` key:
  - Then: must add `lints.workspace = true`.
- If manifest has `lints.workspace = true`:
  - Then: must preserve it.
- If manifest has any other `lints` configuration:
  - Then:
    - Must preserve it.
    - Must fail.

## .mise/tasks/git/repo-name.sh

- Must derive name from final component of `origin`, removing trailing slash and `.git`.
- Must use `MISE_PROJECT_ROOT` or current directory and support GitHub, Keybase, equivalent URL shapes.
- If origin is unreadable or result is empty:
  - Then: must fail.
  - Else: must output only name.

## .mise/tasks/git/install-hooks.sh

- Must install executable `pre-commit`, `pre-merge-commit`, `commit-msg` hooks in Git's resolved hooks directory.
- Hooks must delegate to matching mise tasks and forward all arguments.
- Installation must replace obsolete Lefthook launchers.
- Installation must remove obsolete repository-generated `post-commit` hook without removing user-modified hook.

## .mise/tasks/git/validate-commit.sh

- Must reject active-index entries marked `assume-unchanged` or `skip-worktree`.
- Before checks and after successful checks, must:
  - Require tracked working-tree contents, including submodules, to match active index.
  - Require every nonignored untracked file to be staged or removed.
- Must run `check` task against working tree.
- If active-index tree changes during successful checks:
  - Then: must fail.

## .repoconf/hooks/post-init.sh

- Must accept only initialized directory and derive names from `origin` without prompting.
- Must trust repository and install and reshim mise tools.
- If origin is GitHub:
  - Then: must read repository name, canonical URL with `gh`.
  - Else: must use `git:repo-name` without requiring `gh` or setting repository URL.
- Must remove template license files and run `fix:name`.
- For each package discovered by `cargo metadata`:
  - Empty `package.metadata.details.title`.
  - Remove `package.description`.
  - If no repository URL is available:
    - Then: remove direct `repository` and `homepage`.
- Must always empty `workspace.metadata.details.title` and remove `workspace.package.description`.
- If repository URL is available:
  - Then: must set `workspace.package.{repository,homepage}` to it.
  - Else: must remove `workspace.package.{repository,homepage}`.
- May rely on template root defining workspace fields it updates.
- Must update fnox identifiers, regenerate READMEs, build, test, stage, commit.

## .github/workflows/ci.yml

- Must keep Rust version specified in `rust-toolchain.toml`.
  - Rationale:
    - Setting it to "stable" in CI leads to warnings that aren't visible in pre-commit.
    - Building for both "stable" and pinned version takes extra time and disk space.
    - Pinning "stable" is not always possible (some projects do require nightly).
